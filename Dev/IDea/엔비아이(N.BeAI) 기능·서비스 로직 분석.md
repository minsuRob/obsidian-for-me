# 엔비아이(N.BeAI) 기능·서비스 로직 분석

- 출처: https://chat.beai.kr/intro/ (index.html, guide.html), 2026-10-14 수집
- 범위: 공개된 소개·가이드 페이지 기준. 실제 앱(`/`)은 로그인 뒤 `/static/loader.js` SPA라 내부 로직은 미확인
- 한 줄 요약: **소상공인 사장 전용 AI 경영 파트너** — 역할별 AI 3명 + 매일 밤 마감 일지 + 엑셀 정산 자동 분류

---

## 1. 전체 구조

```
[로그인: 구글/카카오 OAuth] → 72시간 무료 체험 → 구독(크레딧제)
        │
        ├─ 채팅 (AI 파트너 3명)
        │    ├─ 비아이  : 사업 전략 (CSO)  ← 기본, 모르면 여기부터
        │    ├─ 에코    : 재무 전략 (CFO)  ← 정산 데이터 연동
        │    └─ 헤라    : 마케팅 전략 (CMO) ← 카피·콘텐츠·이미지 생성
        │
        ├─ 사장의 생각하는 시간(사생시) : 대시보드 / 정산 / 분석 / 설정
        │    ├─ 일일 마감 (질문 7개 + 수입·지출 + 메모) → AI 조언 + 할 일
        │    ├─ 달력 대시보드 (매출·지출·순이익·이익률·할 일)
        │    └─ 정산 (엑셀/CSV 업로드 → 자동 분류)
        │
        └─ 설정 : 일반 / 개인화 / 대화 / 계정
```

## 2. 기능 상세

### 2.1 개인화 컨텍스트 (두 곳)
| 위치 | 필드 | 쓰이는 곳 |
|---|---|---|
| 엔비아이 설정 › 개인화 | 사업 소개(업종/고객/지역/채널), 운영 구조(영업시간/제공방식), 기타 — 각 300자 | **모든 채팅**의 시스템 프롬프트 |
| 사생시 › 설정 | 가게 이름, 업종, 지역, 설명, 고객은 누구인가, 고객의 구매 목적, 고객 접점 채널 | **일일 마감 조언** |

- 사생시 설정에는 **"분석 요약 생성"** 버튼 → 입력값을 AI가 요약한 "컨설턴트의 분석 요약"을 만들고 사용자가 확인 후 저장.
  → 추정: 긴 원문 대신 이 요약을 매일 조언 프롬프트에 넣어 토큰 절약 + 품질 안정.

### 2.2 채팅 (멀티 페르소나)
- **같은 대화창에서 파트너 전환**: 상단 이름 드롭다운 → 대화 히스토리는 유지하고 시스템 프롬프트만 교체.
- **대화창 간 기억 공유 없음**: 의도적으로 세션 격리 (지난 맥락이 판단을 오염시키지 않게).
- **주제 분리하기(✂)**: 답변 아래 가위 버튼 → 현재까지 대화를 복사한 새 대화 생성 (fork). 말풍선 10개 안팎에서 권장.
- 답변 액션 버튼: 복사(⧉) / 분리(✂) / 음성(♪) / 재생성(↻)
- 파일 업로드(＋): 리뷰 캡처, 상세페이지, 메뉴판, 정산 엑셀 등 → 멀티모달 입력.
- 프롬프트 철학: "만들어 줘"보다 **"네 생각은 어때?"** — AI가 상황을 되묻고, 판단 근거 → 우선순위 → 오늘 할 가장 작은 행동까지 쪼갬. "하지 않아도 되는 일"도 정리.
- 차별점으로 내세우는 3가지: 사업을 이해(내 이익 기준) / 고객을 이해(고객의 선택을 받아야 함) / 현실을 이해(실행 가능한 전략).
- 사이드바: 파트너 목록, 사생시, 첫 사용 가이드, 날짜별 대화 목록, 검색, 보관된 대화, 프로젝트 폴더(예: "모두의창업").

### 2.3 상황별 라우팅 가이드 (UI 추천)
| 상황 | 추천 파트너 |
|---|---|
| 새 사업 시작 전 | 비아이 |
| 마케팅 전략·콘텐츠 | 비아이 → 헤라 |
| 정부지원·투자 준비 | 비아이 → 에코 |
| 할인·재무 결정 | 에코 |

### 2.4 72시간 체험 시나리오 (온보딩)
| 날 | 보낼 것 | 받는 것 |
|---|---|---|
| 첫째 날 | 네이버 플레이스 리뷰 링크/리뷰 글 | 손님이 누구인지, 왜 사는지, 무엇을 원하는지 |
| 둘째 날 | (문의 내역 등) | 문의를 결제로 바꾸는 법 |
| 셋째 날 | (재방문 데이터) | 다시 오게 만들기 |

### 2.5 사장의 생각하는 시간 — 일일 마감 (핵심 리텐션 기능)
**질문 7개** = 고객 반응 3 + 사업 4축 4

| 그룹 | 항목 | 질문 |
|---|---|---|
| 고객 반응 | 칭찬 | 오늘 손님의 긍정적인 피드백은? |
| | 불만 | 아쉬워하셨거나 스스로 아쉬웠던 부분은? |
| | 새로운 기획 | 칭찬받기 위해 무엇을 해보고 싶은가? |
| 4개 축 | 상품 | 잘 팔린 것과 그 이유는? |
| | 모객 | 새 손님은 어떻게 들어왔나? |
| | 접객 | 접객에서 신경 쓴 한 가지는? |
| | 고객관계관리 | 다시 오면 좋겠다 싶은 손님께 어떤 접촉을 했나? |

흐름:
1. "오늘 마감하기" → 1/7 단계별 입력 (빈칸 허용, **자동 임시 저장**)
2. 수입·지출 입력 (정산에 엑셀 올려 두면 입출금 자동 표시)
3. 메모 → 저장
4. AI가 **오늘의 조언**(헤드라인 + 해설) + **할 일 3개** 생성 → 할 일은 "마감" 태그로 To-do에 등록
5. 달력에 일자별 수입/지출/순이익/이익률/할 일 누적. 보기 필터: 같이 보기 / 금액만 / 할 일만
6. 달력의 날짜에서 "새 대화 시작하기" → 그날 기록을 컨텍스트로 채팅

- 질문은 설정에서 가게에 맞게 커스터마이즈 가능.
- 레거시 "사생시 앱" 엑셀 내보내기 파일로 과거 기록 import.

### 2.6 정산 (엑셀 자동 분류)
- 입력: .xlsx / .xlsm / .csv, 10MB 이하, **양식 제각각이어도 OK** (은행/카드사별 포맷 → LLM으로 컬럼 해석 추정)
- 출력 행: 날짜 / 내용 / 분류(매출·원재료·소모품·확인 필요 …) / 금액
- 개인 이체·결제 취소 등 애매한 건 **"확인 필요"(검토 대기)** 로 분리 → 사용자 확인 후 저장
- 요약: 확정 수입 / 확정 지출 / 순이익 / 이익률 / 검토 대기 건수
- **조회한 기간 그대로 에코에게 넘겨 재무 상담** (정산 → 채팅 컨텍스트 연결)

### 2.7 요금 (크레딧제, 품질 동일·사용량만 차등)
| 플랜 | 월 | 일 한도 | 이미지 생성 |
|---|---|---|---|
| Starter | 90,000원 | 65만 크레딧 (질문 30~50회) | 월 75개 미만 |
| Standard (추천) | 180,000원 | 130만 크레딧 (60~100회) | 월 150개 미만 |
| Unlimited | 300,000원 | 무제한 | 월 300개 미만 |
| Enterprise | 상담 | 조직 단위 | — |

- 크레딧 소모: 대화, 대화 기록 저장, 파일 업로드, 문서 만들기 — 작업마다 소모량 다름 (토큰 기반 추정)
- **일 단위 리셋** 한도. 환불 없음, 구독 취소로 자동결제 해지.

## 3. 추정 데이터 모델 (재구현용)

```ts
User { id, provider: 'google'|'kakao', trialEndsAt, plan, dailyCreditUsed, creditResetAt }
Personalization { userId, bizIntro(300), operation(300), extra(300) }

Conversation { id, userId, title, folderId?, archived, createdAt, forkedFrom? }
Message { id, conversationId, role, persona: 'bi'|'eco'|'hera', content, attachments[] }

ShopProfile { userId, name, industry, region, description,
              customers, purpose, channels, analysisSummary }
ClosingQuestion { userId, order, group: 'reaction'|'axis', key, text }   // 커스터마이즈 가능
DailyClosing { userId, date, answers{key:text}, income, expense, memo,
               adviceTitle, adviceBody, status: 'draft'|'done' }
Todo { userId, date, text, source: 'closing'|'manual', done }

LedgerUpload { id, userId, filename, period }
LedgerEntry { uploadId, date, description, category, amount,
              status: 'confirmed'|'needs_review' }
```

## 4. 핵심 로직 추정 (프롬프트 레벨)

- **페르소나 프롬프트** = 공통 원칙(사업·고객·현실 이해, 되묻기, 우선순위, 최소 행동, 안 해도 되는 일) + 역할별 전문성 + 개인화 블록
- **일일 조언 프롬프트** = ShopProfile.analysisSummary + 오늘 7개 답변 + 수입/지출 + 최근 N일 기록 → `{headline, body, todos[3]}` JSON 출력
- **정산 분류** = 엑셀을 행 단위 텍스트로 변환 → LLM이 (날짜, 내용, 금액, 분류, 확신도) 추출 → 확신도 낮으면 `needs_review`
- **주제 분리** = 메시지 배열 복사로 새 Conversation 생성 (`forkedFrom` 기록)

## 5. 알 수 없는 것 (서버 측)
- 실제 시스템 프롬프트, 사용 모델, 크레딧 환산 공식
- 엑셀 파싱/분류 규칙의 실제 구현
- 이 부분은 클라이언트 코드에도 없고 서버에 있어서 웹에서 가져올 수 없음. 비슷하게 만들려면 위 추정으로 직접 설계해야 함.
