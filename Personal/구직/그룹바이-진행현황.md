## 열람 제한과 진행 속도

- 그룹바이는 공고를 빠르게 열면 `[표시 제한]` 가짜 데이터를 보여준다. 자세한 내용은 [[구직리서칭방법]] 참고.
- 탭 1개로 공고 사이 대기 시간을 늘려 가며 시험했다.
  - 2분: 2개 열고 차단
  - 3분: 몇 개 열고 차단
  - **5분(300초): 2026-10-14 18:51 이후 약 170건 연속으로 차단 없음**
- 5분 간격이면 1시간에 약 11~12건이다. 남은 304건은 약 26~28시간 걸린다.
- 중간에 API 연결 오류로 작업이 두 번 끊겼지만, 공고마다 바로 저장해서 손실은 없었다.

## 재개 방법

1. 인앱 브라우저에서 그룹바이 로그인 상태를 확인한다.
2. 연구 데이터는 볼트의 숨김 폴더 `Personal/구직/.groupby-data/`에 백업되어 있다. Obsidian 화면에는 보이지 않는다.
   - `out/<공고ID>.json`: 공고별 조사 결과 (215건)
   - `assemble.py`: JSON을 모아 [[그룹바이]]·[[그룹바이-비개발]]을 다시 생성한다. 기존 목록 정보와 링크는 유지한다.
   - `validate.py`: 저장된 공고명을 원래 목록과 대조해 가짜 데이터를 검출한다.
   - `agent_prompt2.md`: 작업자 지시서 (조사 항목, 5분 간격 규칙, 차단 판정 기준)
   - `b3/*.txt`: 남은 공고 ID 배치 목록 (기존 분류 포함)
   - `orig_dev.md`, `orig_non.md`, `ids2.txt`: 원래 목록과 519개 ID
   - `delay.txt`, `pace.log`: 현재 대기 간격(300초)과 열람 기록
3. `b3/` 배치 순서대로 진행하되 `out/`에 이미 있는 ID는 건너뛴다. 다음 시작 지점은 `b3/06.txt`의 6783 근처이고, 이후 `07`~`16` 배치가 남아 있다.
4. 5분 간격으로 20건씩 처리한다. 배치마다 `validate.py`로 검증하고 `assemble.py`로 두 파일에 반영한다.
5. 마지막에 7250, 10209, 8070을 확인한다. 사이트 표시 520개와 실제 수집 519개의 차이도 다시 확인한다.
