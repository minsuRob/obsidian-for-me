- **주제:** 포트폴리오 구성법 ('문제 해결의 상세함' 덩어리)
- **요약:** 포트폴리오는 PPT처럼 앱 화면 캡처 몇 장 넣고 기능 설명을 나열하는 자료가 아님. 내가 문제를 어떻게 발견했고, 어떻게 해결했으며, 결과가 무엇이 달라졌는지를 상세하게 보여주는 자료.
- **핵심 포인트:**
  - 하나의 '문제 해결의 상세함' 덩어리 = **제목 → 그림 → 문제 → 해결 과정 → 결과**
  - 이런 덩어리 4개 정도를 일관된 형태로 나열하면 됨 (생각보다 복잡하지 않음)
  - 이 순서만 지켜도 가독성이 좋아지고 방향 자체가 달라짐
  - 디자인에 너무 많은 시간 쓰지 말 것

## 68. 포트폴리오 쓰는 방법 – 절대 PPT가 아님! (2026-07-09, 캐러셀 6장) — [링크](https://www.instagram.com/p/DakevHxARve/)
- **주제:** 이력서 vs 포트폴리오 구조
- **핵심 포인트:**
  - 복습(이력서): 이력서는 2~3장, 프로젝트 단위로. 최상단에 사진·지원동기 등 프로필 / 굵직한 프로젝트 단위로 3개 정도 나열 / 각 프로젝트에 문제 해결한 부분 4줄 정도 / 문제 해결은 문제 + 배경 + 결과 + 도메인 구성 / 단순 구현·조직 외 업무도 나열. 포트폴리오 설명하기 전 간단하게 이력서 쓰는 법
  - 포트폴리오: **제목, 그림, 문제 원인 상황, 해결 과정, 결과** 순서
    - 제목: 이력서의 문제 + 배경 + 결과 + 도메인 복붙
    - 그림: 아키텍처, 시퀀스, 수치 그래프 등 보기 좋게
    - 문제: 구체적인 상황, 어떠한 문제인지 3줄
    - 해결: 어플리케이션 깊이까지 상세하게 나열 4줄
    - 결과: 수치 필수, 부하 테스트까지 하면 최고
  - 실제로 쓸 때: 이러한 '하나의 덩어리'가 4개 정도 나열 / 그림은 너무 복잡하게 그리지 않는 것이 중요 / 실제 코드가 있으면 LLM에게 "문제, 배경, 결과" 3줄씩 써줘 하면 뚜→ 유료 만들어줌 / 그것을 계속 수정하면 마음에 드는 결과가 나옴
  - 주의할 점: 절대 PPT가 아님, 발표자료가 아니라는 점 / 첫 번째·두 번째 문제 해결 덩어리에 엄청난 노력을 / 포트폴리오 == 문제 해결 결과의 '상세함'의 나열 / 최상단에 또 자기소개를 쓸 필요 없음 / 이력서와 같이 보기 때문에 절대 프로젝트 설명 XX
  - 정말 생각보다 포트폴리오를 발표자료처럼 만드는 지원자가 굉장히 많음. 이력서는 문제 해결과 구현 등 모든 것을 가독성 있게 키워드 중심으로 쭉 나열했다면, 포트폴리오는 상세하게 '내가 어떤 생각을 가지고 문제를 해결했는지' 그 머릿속 흐름을 보여주는 것

## 129. 포트폴리오와 이력서는 무슨 관계일까? (2026-04-03, 영상 1:43) — [링크](https://www.instagram.com/reel/DWq60n1kTGN/)
- **주제:** 이력서 한 줄 → 포트폴리오 덩어리 + AI 활용
- **핵심 포인트:**
  - 이력서에 간단하게 한 줄로 압축해서 쓴 문제 해결 결과를 포트폴리오에는 그림과 함께 깊게 씀 (깊이는 사람·역량마다 다름). 제목은 그대로 쓰면 됨
  - 그림이 어렵다면 그냥 데이터 흘러가는 대로 그리면 됨 (화살표도 자유, 그게 정답이라 생각하면 됨)
  - 문제 해결 결과는 각각 2~3줄씩. 어렵다면 해결 코드 + 제목 + 기술 스택을 AI에 주고 "문제 해결 결과 3줄씩 써달라" → 무에서 유를 창조. 결과 문장이 별로일 수 있으니 한 번에 끝내지 말고 AI와 1~2시간 놀다 보면 만족스러운 결과가 나옴
  - 이렇게 포트폴리오 덩어리 하나 완성 → 이걸 여러 개. 분량은 면접관이 어느 정도면 괜찮다고 할지 생각해보는 경험도 중요
