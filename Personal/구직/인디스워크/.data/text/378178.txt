팀카이 소개
팀카이(TeamKai)는 KaiCX라는 AI Agent 운영 플랫폼을 만듭니다. 우리의 일은 고객사의 고객센터를 AI로 혁신하는 일입니다.
미션:
모든 기업이 AI를 통해 탁월한 고객 경험을 제공할 수 있도록 돕는다.
비전:
혁신적인 AI 기술로, 과거에는 상상할 수 없었던 고객 경험의 미래를 만들어가는 글로벌 AI 에이전트 기업이 된다.
KaiCX는 ”사람이 진짜 가치를 만드는 일에 집중할 수 있도록 인간의 노동을 AI에 위임하자”는 운영 현장의 문제의식에서 출발한 제품입니다.
우리는 현장 중심으로 일합니다. 함께 빠르게 움직이고, 고객사 현장에서 발견한 패턴을 팀 전체가 학습으로 흡수하는 방식이 우리 작동 원리입니다.
우리의 가치
모든 결정은 다음 가치를 기준으로 합니다.
Customer Obsession
· 고객의 문제 해결에 집착한다.
고객사의 상담센터 혁신이 우리의 존재 이유입니다. 모든 논의의 출발점은 현장의 고객센터와 운영팀이 겪는 문제입니다. 고객의 성공이 곧 우리의 성공이며, 고객이 실질적인 성과를 만들어낼 때 비로소 우리도 성공했다고 말할 수 있습니다.
Own the Outcome
· 끝까지 책임진다.
우리는 산출물이 아니라 결과를 약속합니다. 단순히 기능을 제공하거나 프로젝트를 완료하는 것으로 만족하지 않습니다. 약속한 지표가 움직이고 고객이 성과를 체감할 때까지 우리의 일은 끝나지 않습니다. 우리는 데모로 박수를 받기보다, 운영 지표로 평가받습니다.
Stay Curious, Learn Faster
· 호기심을 잃지 않고, 더 빠르게 배우고 발전한다.
우리는 항상 호기심을 가지고 새로운 기술과 변화를 빠르게 배우고 적용합니다. 완벽함을 기다리기보다 먼저 실행하고, 빠르게 배우며 끊임없이 개선합니다. 프로젝트를 통해 얻은 경험과 인사이트를 자산으로 축적하며 지속적으로 성장합니다.
Journey is the Reward
· 배우고 혁신하는 과정 자체를 즐긴다.
우리는 역사상 가장 빠르고 혁신적인 기술 변화의 변곡점에 서 있습니다. 세상이 바뀌는 모습을 지켜보는 데 그치지 않고, 그 변화를 만들어가는 사람이고자 합니다. 새로운 기술을 누구보다 빠르게 배우고 적용하며, 고객과 산업에 의미 있는 임팩트를 만들어내는 과정 자체를 즐깁니다. 우리에게 혁신은 의무가 아니라, 즐거운 여정입니다.
역할 소개
FDE 인턴은 정규직 FDE 옆에서 한 고객사의 에이전트 빌드와 운영에 함께 들어가, 빌더의 일을 처음부터 끝까지 경험하는 사람입니다. Agent Engineer가 만든 프레임워크를 가지고 정규직 FDE와 페어로 1개 고객사 instance의 한 부분을 직접 만들어보고, 고객사 현장에 함께 들어가 운영팀의 일을 옆에서 관찰하며 도메인을 흡수합니다. 인턴 기간이 끝날 때는 본인이 만든 한 모듈이 실제 고객사 운영에서 돌고 있는 상태를 목표로 합니다.
이 역할의 핵심은 빌더로서의 출발점을 가장 빠르게 잡는 자리라는 점에 있습니다. 팀카이는 FDE 인턴 → FDE 정규직 → Agent Engineer 정규직이라는 성장 경로를 공식적으로 열어두고, 그 첫 단계를 누구나 본인의 속도로 시작할 수 있게 합니다. 코드 한 줄, 프롬프트 한 줄이 진짜 고객사 운영팀의 일을 바꾸는 경험을 입사 6개월 안에 만나게 됩니다.
회사 입장에서 보면, 이 자리는 다음 세대 FDE와 Agent Engineer가 시작되는 자리입니다.
주요 업무
정규직 FDE와 페어로 한 부분을 직접 빌드합니다.
Agent Engineer가 만든 프레임워크를 가지고, 정규직 FDE가 담당하는 고객사 instance의 한 모듈(예: 특정 intent 처리, 한 외부 API 연동, 한 가드레일 룰)을 직접 만들어봅니다. 첫 PR은 작아도 좋습니다. 인턴 기간 안에 본인이 만든 모듈이 실제 고객사 운영에서 돌고 있는 상태를 목표로 합니다.
고객사 현장에 함께 들어갑니다.
정규직 FDE와 같이 고객사 현장에 출장해, 그 회사의 CS 운영을 옆에서 직접 관찰합니다. 문의 유형 · 정책 · 예외 케이스 · 톤을 흡수하고, 이후 빌드 작업에 어떻게 반영해야 할지를 사내에서 함께 정리합니다.
운영 데이터를 매일 봅니다.
출시된 봇의 실제 대화 로그를 매일 들여다보고, 실패 케이스를 태깅하며 원인을 추정합니다. Agent PM · 정규직 FDE와 짝을 이뤄 그 추정을 다음 이터레이션의 가설로 옮기고 검증합니다.
배우는 과정을 자산으로 남깁니다.
인턴 기간 동안 본인이 어떤 도메인 패턴 · 빌드 절차 · 디버깅 방법을 익혔는지를 사내에 남깁니다. 다음 FDE 인턴이 같은 시행착오를 반복하지 않도록 하는 것이 인턴 기간의 또
다른 산출물입니다.
성장 경로
팀카이는 FDE 인턴 → FDE 정규직 → Agent Engineer 정규직이라는 성장 경로를 공식적으로 운영합니다. 인턴 자리는 그 출발점입니다.
인턴 기간: 정규직 FDE와 페어로 1개 모듈을 직접 빌드해 실제 고객사 운영에 올립니다. 한 도메인의 CS 흐름을 흡수하고, 본인이 만든 패턴을 사내에 남깁니다.
정규직 전환: 인턴 기간 동안의 산출물 · 도메인 흡수 속도 · 협업 호흡을 본인과 회사가 함께 평가합니다. 합의가 되면 FDE 정규직으로 전환되며, 정규직 FDE의 성장 경로(정착 → 확장 → 분화 → Agent Engineer)로 합류합니다.
필요한 역량
LLM 기반 제품에 대한 직접적인 흥미. 직접 만들어본 작은 프로젝트가 있거나, 빠르게 익혀가며 만들 수 있는 학습력
기본적인 코딩 역량 (언어 무관). 외부 API 호출, 간단한 자동화, 데이터 가공 정도를 막힘 없이 할 수 있는 수준
새로운 도메인을 빠르게 흡수하는 학습력. 익숙하지 않은 운영 현장에서 핵심 패턴을 빨리 추려내려는 호기심
실패 케이스 · 대화 로그를 들여다보고 “왜 이 답이 나왔는가”를 끝까지 따라가는 끈기
고객사 운영팀과 직접 대화하며 배우는 데 거부감이 없는 태도. 출장과 현장 관찰을 인턴 경험의 일부로 받아들이는 마음
우대 사항
LLM 평가 체계나 개발 도구 · 라이브러리를 다뤄본 경험
Forward-deployed 또는 solutions · implementation · 컨설팅 엔지니어 경험
CS · 컨택센터 · BPO 도메인 경험. 특히 여행 · GDS · 이커머스 도메인 경험
스타트업 0→1 또는 창업 경험 (technical generalist 성향)
TypeScript / Node.js 환경 경험
일본어 또는 영어 비즈니스 커뮤니케이션 (글로벌 고객 대응)
우리가 선호하는 인재
이론으로만 LLM을 다뤄본 게 아니라, 작더라도 본인의 손으로 직접 만들어본 적이 있는 사람
“이건 인턴 일이 아니다”라는 선을 긋지 않고, 빌드 · 운영 · 현장 출장 어느 쪽이든 가져가 보려는 사람
처음 보는 도메인의 현장에 들어가서도 위축되지 않고, 1주일 안에 핵심 용어와 흐름을 익히는 학습 속도
본인이 만든 모듈이 실제 사용자에게 도달했을 때의 변화를 보고 싶어 하는 사람
FDE 인턴 → FDE 정규직 → Agent Engineer 정규직이라는 성장 경로를 본인의 출발점으로 받아들이는 사람
보상 및 업무 환경
고용 형태: 인턴 (기간 협의, 통상 3 ~ 6개월). 인턴 종료 시 본인과 회사가 합의하면 FDE 정규직 전환 가능
6인 초기 팀의 일원으로 빌더의 일을 처음부터 끝까지 경험합니다.
처우: 경력 단계에 맞춘 협상. 인턴은 스톡옵션 대상이 아니며, 정규직 전환 시 적용 시작
근무: 서울 도곡동 오피스. 주 4일 출근 + 주 1일 재택 (원하면 출근 가능). 단, 출장 일정에 따라 근무지 변동
출장: 정규직 FDE와 페어로 고객사 현장 출장 동행
