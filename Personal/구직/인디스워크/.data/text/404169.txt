팀 소개
프로덕트팀은 패스오더 유저와 점주님을 연결하고, 고객의 문제를 집요하게 파고들어 더 나은 경험을 만들어요. 빠르게 학습하고 실행하며, 안정성을 기반으로 혁신과 실질적인 비즈니스 임팩트를 만들어갑니다.
Backend 파트는 PRD 분석부터 설계·개발·문서화까지 전 과정에 AI를 활용해(Claude Code 상시 사용, n8n·Make로 반복 업무 자동화) 단순 구현 시간을 줄이고, 설계와 비즈니스 로직, 성능 개선 등 본질적인 문제 해결에 더 집중하는 개발 방식을 만들어가고 있습니다. 스쿼드 단위로 PM·디자이너·프론트엔드와 스프린트 계획부터 함께 참여해 기획에 의견을 내고, Datadog·ElasticAPM으로 시스템 상태를 보며 성능을 개선합니다. 정해진 문화에 적응하기보다, 더 나은 개발 방식을 함께 고민하고 만들어갈 동료를 찾고 있어요.
이를 위해 Backend Developer를 모시게 되었어요. 이 포지션은 주문·결제·정산·적립·이벤트 등 복잡한 비즈니스를 명확한 도메인 모델로 풀어내고, 증가하는 트래픽 속에서도 안정적으로 동작할 수 있도록 시스템을 지속적으로 설계하고 개선하는 역할을 담당합니다.
이런 경험이 꼭 있어야 해요!
이 포지션에는 특정 언어에 국한되지 않는 문제 해결 역량뿐 아니라,
성능과 확장성을 고려해 데이터 모델과 쿼리를 최적화하고 RESTful API를 직접 설계·개선해본 경험이 반드시 필요해요.
Kotlin·Python·Java 등 다양한 환경의 개발 경험이 풍부하더라도 이러한 경험이 없거나, AI 개발 도구로 생산성을 높이려는 의지가 없다면 이번 포지션과는 맞지 않아요.
어떤 기술적 문제를 마주했고 이를 어떻게 해결했는지, AI 개발 도구와 프롬프트 엔지니어링을 활용해 개발 방식과 생산성을 어떻게 개선했는지를 중심으로 소개해 주세요.
◈ 서류에서 해당 경험의 보유 여부와 깊이를 확인하기 어려운 경우, 실제 역량이 있더라도 다음 전형으로 이어지지 않을 수 있어요. 서로에게 아쉬운 결과가 생기지 않도록 관련 경험이 명확히 드러나게 작성해 주세요.
이런 업무를 하게 되실 거예요!
○ 도메인 설계 | 복잡한 비즈니스를 명확한 모델로 풀어냅니다
주문·결제·정산·적립·이벤트처럼 서로 얽힌 비즈니스를 DDD 기반으로 모델링하고, 도메인 이벤트 중심으로 서비스 흐름을 설계합니다. 도메인의 경계가 명확해야 기능이 늘어나도 시스템이 흔들리지 않기 때문입니다.
○ API 설계 | 함께 쓰기 좋은 API를 만듭니다
RESTful API를 설계하고 OpenAPI Spec으로 명세해, 프론트엔드·클라이언트 개발자가 헷갈림 없이 협업할 수 있게 합니다.
○ 성능 최적화 & 트러블슈팅 | 문제의 원인을 끝까지 파고들어 개선합니다
증가하는 트래픽 속에서 발생하는 문제의 근본 원인을 추적하고, 쿼리 실행 계획 분석과 데이터 모델·시스템 구조 개선을 통해 체감 가능한 성능 개선을 만들어냅니다.
○ MSA 개발 | 분산 환경에서도 데이터 정합성을 지킵니다
Kafka 비동기 메시지, CQRS, Redis 캐싱, 분산 트랜잭션을 다루며, 결제·정산처럼 한 건도 틀리면 안 되는 데이터를 안정적으로 처리합니다.
○ AI-Driven Development | AI로 구현 시간을 줄이고 설계에 집중합니다
요구사항 분석부터 태스크 산정, 개발, 문서화까지 AI를 활용하고, 반복 업무는 n8n·Make로 자동화합니다.
◈ 이 역할은 AI를 활용해 단순 구현보다 더 높은 수준의 기술적 문제에 집중하고, 다양한 비즈니스 도메인과 복잡한 시스템을 직접 다루며 개발자로서의 문제 해결 범위를 넓힐 수 있어요. 기능을 구현하는 개발자를 넘어 설계와 아키텍처, 비즈니스 로직, 성능까지 고민하며 프로덕트의 기술적 의사결정에 주도적으로 참여하는 개발자로 성장할 수 있어요.
