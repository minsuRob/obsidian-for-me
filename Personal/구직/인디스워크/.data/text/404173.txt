프로덕트팀은 패스오더 유저와 점주님을 연결하고, 고객의 문제를 집요하게 파고들어 더 나은 경험을 만들어요. 빠르게 학습하고 실행하며, 안정성을 기반으로 혁신과 실질적인 비즈니스 임팩트를 만들어갑니다.
패스오더는 현재 WPF 기반의 점주용 PC 주문접수 애플리케이션을 운영하는 동시에, Electron 기반 React Native 앱을 새롭게 만들고 있어요. MVP 테스트를 거쳐 신규 앱으로 완전히 전환할 예정이며, 전환 전까지는 두 앱이 안정적으로 공존해야 해요.
이를 위해 Windows Developer를 모시게 되었어요. 기존 WPF 앱의 기능과 구조를 분석해 React Native·TypeScript 기반의 신규 앱으로 옮기고, API·Socket 통신과 프린터 연동 등 매장 운영의 핵심 기능을 새 환경에서 구현해요. 공존 기간에는 기존 앱을 안정적으로 운영하면서 MVP부터 완전 전환까지 전 과정을 함께 설계하고 실행하는 역할이에요.
이런 경험이 꼭 있어야 해요!
이 포지션에는 C#·WPF와 .NET Framework에 대한 이해뿐 아니라,
React Native·TypeScript로 개발해본 경험과 RESTful API 연동·Socket 통신 기반의 응용프로그램을 직접 개발·운영한 경험이 반드시 필요해요.
기존 WPF 앱의 기능을 분석할 수 있더라도 이를 신규 환경으로 옮기거나, 공존 기간 동안 두 앱을 안정적으로 운영할 역량이 없다면 이번 포지션과는 맞지 않아요.
기존 앱의 어떤 기능과 구조를 분석했는지, React Native·TypeScript 환경에서 무엇을 개발했는지, API·Socket 통신과 프린터 연동 등 핵심 기능을 어떻게 구현·운영했는지를 중심으로 소개해 주세요.
◈ 서류에서 해당 경험의 보유 여부와 깊이를 확인하기 어려운 경우, 실제 역량이 있더라도 다음 전형으로 이어지지 않을 수 있어요. 서로에게 아쉬운 결과가 생기지 않도록 관련 경험이 명확히 드러나게 작성해 주세요.
이런 업무를 하게 되실 거예요!
○ 신규 앱 개발 | 주문접수 앱의 기반과 MVP를 만들어요
React Native·TypeScript와 Electron을 활용해 신규 주문접수 앱의 구조와 핵심 사용자 흐름을 설계하고 MVP를 개발해요.
○ 기능 이관 | 기존 WPF 앱의 핵심 기능을 새 환경에서 구현해요
기존 앱의 기능과 구조를 분석해 RESTful API·Socket 통신, 프린터 연동 등 매장 운영에 필요한 기능을 신규 앱으로 옮겨요. 기능별 전환 범위와 순서를 정하고 전체 기능을 단계적으로 탑재합니다.
○ 배포·전환 | 검증을 거쳐 신규 앱으로 완전히 전환해요
MVP를 매장에 적용해 기능과 안정성을 검증하고, 적용 매장과 범위를 단계적으로 확대해요. 전환 기간에는 기존 WPF 앱과 신규 앱을 병행 운영하며 운영 영향을 최소화하고, 최종적으로 신규 앱에 완전히 안착하도록 관리합니다.
◈ 이 역할은 점주님이 매일 사용하는 주문접수 앱을 Electron 기반 React Native로 새롭게 만들고, MVP부터 기존 앱과의 공존을 거쳐 완전 전환까지 전 과정을 경험할 수 있어요.
