# LLM Wiki와 AI 에이전트 작업환경

## 배경

개인 메신저에 저장된 링크를 계기로 현재 `Work/Robert-LLMWiki`를 점검하고, LLM Wiki의 목적과 기존 AI 개발 자료를 연결했다. 링크 원문과 확인 상태는 [[2026.10.6 링크 메모 정리]]에 보존한다.

## 분석: LLM Wiki의 역할

카파시의 [LLM Wiki 제안](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f)은 매 질문마다 원문을 다시 검색하는 방식과 달리, 출처를 읽은 뒤 기존 Markdown 지식에 통합해 시간이 지날수록 누적되는 구조를 제안한다. 여기서 핵심은 파일 수가 아니라 아래의 유지 루프다.

- **원본 보존**: 출처와 원문을 변경하지 않고 언제든 근거를 확인할 수 있게 한다.
- **정제·연결**: 반복해서 쓸 사실과 해석을 주제 페이지에 정리하고 관련 문서끼리 링크한다.
- **색인·이력 갱신**: `INDEX.md`는 주제별 길잡이, `LOG.md`는 시간순 작업 이력으로 각각 유지한다.
- **검증·재평가**: 새 출처가 기존 주장과 다르면 조용히 덮지 않고 근거·시점·상충을 기록한다.

현재 저장소에는 `CLAUDE.md`, `INDEX.md`, `LOG.md`, `raw/`, `wiki/` 구조가 있어 기본 설계는 이미 맞다. 점검에서 확인한 개선점은 스키마에 `Work/Markhub-LLMWiki`라는 이전 경로가 남아 있고, 색인에는 3개 일감과 2개 리서치만 있어 실제 Wiki 문서 대부분을 찾을 수 없다는 점이다. 본문이 한두 줄이거나 비어 있는 일감 메모도 있으므로, 없는 정보는 보충하지 말고 색인에 `초안/내용 부족`임을 표시해야 한다.

## AI 개발 자료에서 얻은 관점

### 여러 에이전트를 다루는 작업환경

- [Mymux 저장소](https://github.com/ChoiGyber/Mymux)는 여러 셸·SSH/SFTP·파일 탐색기·뷰어·브라우저를 한 창에서 다루는 터미널 멀티플렉서다. README 기준 범용 터미널 도구이며 에이전트 상태를 해석하는 제품으로 소개되지는 않는다.
- [Herdr 리뷰](https://memoryhub.tistory.com/entry/%F0%9F%90%91-Herdr-%EB%A6%AC%EB%B7%B0-%EC%97%AC%EB%9F%AC-AI-%EC%BD%94%EB%94%A9-%EC%97%90%EC%9D%B4%EC%A0%84%ED%8A%B8%EB%A5%BC-%ED%84%B0%EB%AF%B8%EB%84%90-%ED%95%98%EB%82%98%EB%A1%9C-%EB%B3%B4%EB%8A%94-%EB%A9%80%ED%8B%B0%ED%94%8C%EB%A0%89%EC%84%9C)는 Claude Code·Codex 세션을 한 터미널에서 패널로 관리하고, 에이전트 상태를 색으로 보여주는 도구로 설명한다. 이는 사용자의 [[오픈 헤르메스 개발]] 및 [[에이전트 활용법]]에 연결되는 비교 사례다.
- 두 도구의 차이는 “터미널 패널 제공”과 “에이전트 상태를 이해하고 관리”하는 범위다. 실제 기능·지원 OS·유지 상태는 도입 전 각 프로젝트의 최신 문서로 재확인해야 한다.

### 에이전트 도구 연결은 필요에 따라 선택

[GeekNews의 MCP 비판 글](https://news.hada.io/topic?id=34059)은 에이전트가 이미 HTTP API나 CLI를 직접 쓸 수 있는 상황에서는 MCP 래핑이 중복일 수 있고, 도구 정의가 컨텍스트를 차지할 수 있다고 주장한다. 이는 특정 글의 견해이며 MCP 일반의 결론으로 취급하지 않는다. Wiki에 적용할 실무 질문은 “이 도구가 인증·발견·권한·안정성 면에서 직접 호출보다 어떤 이점을 제공하는가?”다.

[Claude Code 업무 자동화 강의](https://www.inflearn.com/course/practical-workflow-a?cid=344586)는 Skills, MCP, 메타 프롬프팅 및 반복 업무 자동화를 다루는 강의 소개다. [Obscura 소개 글](https://fornewchallenge.tistory.com/entry/%F0%9F%A6%80-Obscura-%EC%84%A4%EC%B9%98%C2%B7%EC%82%AC%EC%9A%A9-%EA%B0%80%EC%9D%B4%EB%93%9C-25%EB%A7%8C-%EC%8A%A4%ED%83%80-Rust-%ED%97%A4%EB%93%9C%EB%A6%AC%EC%8A%A4-%EB%B8%8C%EB%9D%BC%EC%9A%B0%EC%A0%80-30MB%EB%A1%9C-Chrome-%EB%8C%80%EC%B2%B4)는 에이전트·스크래핑을 위한 헤드리스 브라우저를 설명한다. 모두 도구 탐색의 단서이지, 성능·보안·품질이 독립 검증된 결과는 아니다.

## 권장 운영 방식

1. 개인적이고 잡다한 링크는 `Personal/keep`의 날짜별 아카이브에 모으고, AI·업무에 재사용할 가치가 있는 지식만 Wiki로 승격한다.
2. Wiki 페이지에는 주장, 출처 링크, 확인일, 확인 한계를 함께 적는다. 페이지 소개 문구만 본 경우에는 “사이트 소개 기준”으로 한정한다.
3. 기존 문서와 관련 없으면 새 페이지를 만들지 않는다. 관련 문서가 있으면 새 페이지와 기존 문서 양쪽에 `[[링크]]`를 추가한다.
4. 매 ingest 후 새 페이지뿐 아니라 실제 존재하는 Wiki 파일 전체가 `INDEX.md`에서 검색되는지 확인하고, 완료 내역을 `LOG.md`에 추가한다.
5. 원문에 민감정보가 섞인 개인 메모는 통째로 업무 Wiki `raw/`에 복제하지 않는다. 필요한 사실과 공개 출처만 분리해 기록한다.
